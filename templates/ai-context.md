# Post title — AI context dump

## Current result and remaining work

State the verified result first. List anything still unverified or unresolved.

## User intent and constraints

Preserve accepted preferences, rejected approaches, protected settings and scope.

## Environment and initial symptoms

Include relevant hardware, software versions, connection topology, configuration paths and the initial failure. Separate measured values from user reports.

## Evidence and diagnosis

Link original inputs and logs in `evidence/`. Explain what proves the diagnosis, what is inferred, and what the evidence does not establish.

## Investigation and failed attempts

Record useful negative results and corrections, including why earlier fixes were incomplete. Preserve their evidence.

## Final implementation

Explain each changed file, its role, important assumptions and interactions. Put runnable supporting files in `files/` and identify the version actually deployed.

## Reproduce and adapt

Give exact commands and working directories. Identify host-specific values that require fresh discovery. Distinguish tested procedures from later documentation examples.

## Validation

Record commands, results, human feedback, and practical limits. A partial reboot check is not a full pass. Keep raw output in `evidence/`.

## Rollback and recovery

Explain how to undo only this change, preserve unrelated state, and recover access if undo restores the original problem.

## Sources and provenance

Include primary references, evidence origins and useful timestamps. Never include credentials or authentication cookies.

## Privacy and migration notes

Identify redacted fields and the technical identifiers deliberately retained. If consolidating an older repository, preserve its licence, working files and provenance; distinguish historical links from dependencies required by the new instructions. Check issues, releases, assets and history before claiming the source is no longer needed.
